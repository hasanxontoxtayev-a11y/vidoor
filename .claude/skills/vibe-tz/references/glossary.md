# Plain-language glossary (Modes 4 & 5)

Use these analogies when a word first appears. Translate into the student's language; adapt the analogy to their project (a shop, a school, a bot…). One or two sentences is enough — then go back to building.

## The big picture

| Word | Plain explanation | Analogy |
|---|---|---|
| **Website / web app** | Pages that open in a browser. An *app* also remembers things and knows who you are. | A poster on the wall vs. a shop with a cashier. |
| **Frontend** | The part people see and click. | The shop window and the sales floor. |
| **Backend / server** | The part that works behind the scenes: saves data, checks passwords. | The kitchen of a restaurant. Guests don't see it, but the food comes from there. |
| **Database** | Where information is stored in tables. | A big, smart Excel file that never gets lost. |
| **API** | The way two programs ask each other for things. | A waiter: you order, the waiter brings it from the kitchen. |
| **Bot** | A program that chats in Telegram on its own. | A shop assistant who never sleeps and answers instantly. |
| **Code** | Written instructions for the computer. | A recipe — the computer follows it step by step. |
| **Framework (Next.js, aiogram)** | Ready-made building blocks so we don't start from zero. | A house kit with walls already made — we arrange and decorate. |
| **Vibe coding** | Building software by describing what you want to an AI, then checking and steering. | Being the film director: AI is the camera crew, you decide the story. |

## Tools in our class

| Tool | Plain explanation | Analogy |
|---|---|---|
| **Git** | Saves snapshots of your project so you can go back any time. | Save points in a video game. |
| **Commit** | One saved snapshot with a note about what changed. | One save point with a label: "added the menu". |
| **GitHub** | A website that keeps your Git project online. | Google Drive for code — plus the history of every change. |
| **Repository (repo)** | One project's folder on GitHub. | One shelf in a library for your project. |
| **Push** | Sending your saved commits from your computer to GitHub. | Uploading your save file to the cloud. |
| **Deploy** | Putting your project on the internet so anyone can open it. | Moving your shop from your bedroom to a real street. |
| **Netlify / Vercel** | Services that deploy websites automatically every time you push to GitHub. | A landlord that rebuilds your shop window overnight whenever you change the design. |
| **Supabase** | A ready-made backend: database, login and file storage. | A rented office with a filing cabinet, a security guard and a storage room. |
| **Railway** | A computer in the cloud that runs your program 24/7. | A night-shift worker who keeps your bot awake while you sleep. |
| **BotFather** | Telegram's official bot that creates new bots and gives you a token. | The registration office that issues your bot's ID card. |

## Words that come up while building

| Word | Plain explanation | Analogy |
|---|---|---|
| **Domain / URL** | The address of your site. | The street address of your shop. |
| **Environment variable (.env)** | A secret value kept outside the code (passwords, keys). | A safe: the code knows the safe exists but the secret isn't written on the wall. |
| **API key / token** | A secret password that lets your program use a service. | The key to your shop. Never give a copy to strangers. |
| **Auth / login** | Checking who the user is. | The guard at the door checking ID cards. |
| **Row Level Security (RLS)** | Database rules saying who can see which rows. | Each student can open only their own locker. |
| **Table / row / column** | A table holds one kind of thing; each row is one item; columns are its details. | A class register: each row is a student, columns are name, phone, grade. |
| **Terminal** | A window where you type commands to the computer. | Talking to the computer by text instead of clicking. |
| **Package / library (npm, pip)** | Code other people wrote that we can reuse. | Buying ready-made bricks instead of making your own. |
| **Bug / error** | Something not working as expected. Completely normal. | A typo in a recipe — find it, fix it, cook again. |
| **Log** | Messages a program writes about what it's doing. | A ship captain's diary — read it to see what went wrong. |
| **Long polling** | The bot keeps asking Telegram "any new messages?" | Checking your mailbox every few seconds. |
| **Webhook** | Telegram calls your server when a message arrives. | The postman rings your doorbell instead of you checking the box. |
| **Responsive / mobile-first** | The site rearranges itself to look good on phones. | Furniture that folds to fit a small room. |
| **MVP** | The smallest version that's already useful. | First a bicycle, later a car — not half a car. |
| **TZ (texnik topshiriq)** | The written plan of what we're building. | The architect's drawing before building a house. |
